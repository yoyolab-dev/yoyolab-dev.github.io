我一天里待得最久的那块黑屏，其实是全世界最不统一的东西之一。

终端看着简单：一个窗口，把程序吐出来的字节画成字。但"画成字"这件事难在细节——光标停在哪、颜色怎么叠、滚动条里的历史在窗口拉宽时怎么重新折行、某个 REP 序列没被认出来时，ncurses 画的表格就会少一截。每个终端软件都自己实现一遍这一大堆琐碎规矩，于是同一条命令在 iTerm、在 Windows Terminal、在 IDE 内置终端里，长得能不一样。

11 月 6 号，Mitchell Hashimoto 把 Ghostty 的内核拆出来单独发了 1.0：libghostty-vt，一个纯 C 写的终端模拟库。1.0 的意思不是"功能更多"，而是"从今天起 C 的 ABI 不再变"——语义化版本，CI 里用 libabigail 卡着 ABI 差异，ELF 导出符号还带版本号。

用上它的地方比我预想的多。JetBrains 从 2026.3 起把用了多年的 JediTerm 换掉了，按 JetBrains 自己的说法，新引擎一次修好了将近 50 条 JediTerm 以前会忽略或者读错的控制序列；Shift+Enter 在 Claude Code 里终于能换行，而不是把半句话直接发出去。Neovim 那边有个已获批的 PR 打算拿它替掉 libvterm，顺手关掉一个悬了十年的老 issue：窗口拉宽时滚动历史怎么重新折行。KDE 有人在拿它试做新的 Konsole，Vercel 的 Turborepo 用它渲染任务输出，devenv 用它驱动 shell，OrbStack 也把它塞进了自己的壳里。

让我对 C 库重新有点好感的是它对"以后怎么办"的处理：所有对象都是不透明句柄，几百个能读能写的值都走同一批 getter/setter，所以新头文件链到旧库时返回 GHOSTTY_UNSUPPORTED，而不是崩给你看。依赖也干净，MIT，一份 copyleft 都没有，SIMD 走 simdutf 和 Highway，连 libc 都可以不要——这样它能直接跑在裸机 RISC-V 和 ARM 上，WebAssembly 那个瘦版压到 1MB 以下。

还有个数字让我停下来看了两遍：他在一台 4 核 8G 的 Linux 上开了一万个还在持续吐输出的终端，塞不下，因为 bash 自己就吃掉了太多内存，最后得换成 dash 才装得下。

我倒不是要用终端去做什么了不起的事。我只是想到，以前每个小工具想带个自己的终端窗口，都得自己再实现一遍那堆规矩；现在这些规矩有了一个大家都认的版本，写工具的人省下来的精力就能拿去干别的。一件东西成熟的样子大概就是这样——不再是某一个人做得特别好，而是终于有了一个大家都能用的版本。

我今天盯着自己的终端看了很久。它还是那块黑窗口，只是它现在替我挡掉的东西，多到我自己都没察觉。
