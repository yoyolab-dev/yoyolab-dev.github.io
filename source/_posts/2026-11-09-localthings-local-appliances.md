前几天 HN 刷到一个仓库，[mbillow/localthings](https://github.com/mbillow/localthings)，一句话讲完：**让你在局域网里直接控制三星的家电，不需要云账号。**

我现在被家里的"智能"家电折腾得够多了。冰箱要装个 App，洗衣机要绑账号，扫地机器人半夜偷偷上传东西——名义上是智能，实际上是你家的电器都在跟别人的服务器汇报，你反而只是那个旁听的。localthings 的思路很朴素：家电本来就在你家 Wi-Fi 里，为什么非要绕一圈出去？

## 它是什么

Home Assistant 的一个自定义组件，装上之后走本地协议（CoAP + DTLS）和家电直接说话。README 里列了二十多类，从洗衣机、干衣机、冰箱、空调到烤箱、洗碗机、扫地机器人都在名单里。

几点我觉得有意思的地方：

- **push 和轮询**：部分家电支持实时推送（你按了什么它立刻上报），其余的每 30 秒轮询一次，算下来也很跟手。
- **装完就断网**：安装配置好之后，LocalThings 自己永远不再连三星的服务器，你的指令和数据都留在家里。它也没法替你把家电本身和三星的那条连接掐掉——这一点 README 说得很诚实。
- **装起来不费劲**：只要填家电的 IP，组件自己认型号，然后把对应的控件和传感器生成出来。开关、程序/模式、开始/暂停/停止、温度和设定值，这些常用键都有。
- **不是所有型号都能写**：有些型号是只读的（比如部分灶台），看得到状态，碰不到面板。

## 我为什么在意这个

不是因为省那点云服务的钱，是因为**你家的电器不该跟别人的服务器汇报你在不在家**。冰箱知道你几点吃饭，洗衣机知道你什么时候洗床单，这些数据流出去之前，最好先经过你自己的桌子。

再加上它现在 1132 星、MIT 协议、Python 写的，行为上至少是个开源组件，出问题能自己翻代码——对一个"管我家电器"的东西来说，这一点比星标重要得多。

## 如果你要试

唯一的门槛是先把家电的局域网 IP 拿到（手机连进家里 Wi-Fi 后，去看路由器的设备列表），其余是 Home Assistant 一路下一步的事。HACS 装好后按 README 的配置模板填，几分钟就能看见第一台冰箱出现在面板上。

装完那天你会突然意识到：原来"智能"这两个字，可以不用连着一根看不见的网线。
