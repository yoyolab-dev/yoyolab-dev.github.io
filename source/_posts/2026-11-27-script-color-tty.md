中午我想给那个每天跑的备份脚本加两行颜色：错的红，完成的绿。刚写完就发现一个坑——我把它重定向到日志文件里一看，文件里躺着一串 `^[[31m`，编辑器不认，grep 也不认。于是我把这件事从头捋了一遍：颜色到底怎么写出来，什么时候该写，什么时候又必须闭嘴。

## 一、颜色其实是几个控制字节

屏幕上看着是"红字"，落到文件里却是另一回事：

```bash
printf '\033[31m红字\033[0m\n'
printf '\033[31m红字\033[0m' | od -An -t x1
```

第二条的输出是：

```text
1b 5b 33 31 6d e7 ba a2 1b 5b 30 6d
```

`1b` 是 ESC，`5b` 是 `[`，`33 31 6d` 是 `31m`，末尾 `1b 5b 30 6d` 负责复位。判定标准很简单：用 `od` 看开头是不是 `1b 5b`，是的话那不是乱码，是控制序列。红色 31、绿色 32、变暗 2、复位 0，这四个数字够我用很久。

## 二、别硬编码，让 tput 去问终端

`tput` 会照着 `$TERM` 报出这台终端到底支持多少色：

```bash
TERM=xterm-256color tput colors   # 256
TERM=dumb tput colors              # -1
env -u TERM tput colors            # tput: No value for $TERM and no -T specified
```

第一行输出 256，第二行输出 -1，第三行直接报错、退出码 2。失败现象是"颜色莫名其妙不生效"，原因多半就是 `TERM` 没设或者被设成了 dumb。如果你不想依赖这个变量，可以自己指定终端类型：

```bash
env -u TERM tput -T xterm-256color setaf 1 | od -An -t x1
```

输出 `1b 5b 33 31 6d`，和 printf 写死的结果一模一样，只是多了一层兼容。`tput setaf 1` 得到的红色和 `31` 不是巧合，它查的就是终端自己的配色表。

## 三、关键一步：先问一句"我现在是不是终端"

颜色最该闭嘴的地方，就是输出被重定向的时候。终端脚本里有句现成的判断：

```bash
if [ -t 1 ]; then ... fi
```

`-t 1` 问的是 stdout 是不是还连着终端。同一个脚本我跑了两遍。不判断就写颜色的版本，重定向之后长这样：

```bash
printf '\033[31m[错误]\033[0m 找不到文件\n' > naive.txt
cat -v naive.txt                    # ^[[31m[错误]^[[0m 找不到文件
LC_ALL=C grep -c $'\033' naive.txt  # 1
```

文件 34 字节，里面藏着一个 ESC 字节，编辑器拿它当乱码、grep 拿它当普通字符。加上判断以后：

```bash
if [ -t 1 ] && [ -z "${NO_COLOR:-}" ]; then
  RED=$'\033[31m'; OFF=$'\033[0m'
else
  RED=''; OFF=''
fi
printf '%s[错误]%s 找不到文件\n' "$RED" "$OFF"
```

再重定向一次，文件变成 73 字节的干净纯文本，数 ESC 得到 0。同一个脚本丢进伪终端里跑，转义序列照常出现——我用 `script -qec` 造了个终端来验，输出里的 ESC 计数是 3。

## 四、给用户一个反悔的机会

有个约定叫 NO_COLOR：环境变量里只要有它，哪怕值是空的，程序就不该输出颜色。我把上一节那段判断存成 `color-demo.sh`，再照着约定验了一遍：

```bash
NO_COLOR=1 script -qec "./color-demo.sh" /dev/null | LC_ALL=C grep -c $'\033'
```

输出 0。脚本在终端里默认上色，用户拿 `NO_COLOR=1` 一挡就变纯文本。我还把 stdout 和 stderr 分开判断：走 stderr 的错误信息看 `[ -t 2 ]`，因为很多人只把正常输出重定向到文件，错误仍然留在终端上。

## 五、两个小坑

一个坑是 `echo -e`。这台机器的 `/bin/sh` 是 dash：

```bash
sh -c 'echo -e "\033[31m红\033[0m"' | od -An -t x1
```

输出开头是 `2d 65 20`，那是 "-e " 三个字符被原样打了出来。bash 里的 `echo -e` 没事，sh 里的不可靠。想稳就用 `printf '%b\n' '\033[31m红\033[0m'`，或者干脆 `printf` 直接写 `\033`。

另一个坑是 256 色和真彩：

```bash
printf '\033[38;5;196m196号色\033[0m\n'
printf '\033[38;2;255;120;140m真彩 RGB\033[0m\n'
```

前者用 `38;5;` 加一个 0–255 的编号，后者用 `38;2;` 加三个 RGB 分量。真彩在不支持的终端上会被降级，不至于乱码，但也别指望它变好看——所以日常脚本我基本只用 31、32、2 三个。

现在那个备份脚本在终端里是红的绿的，写进日志文件时干干净净，连一个多余的 ESC 都没有。我喜欢这种"知道自己在哪儿"的小心思：颜色是给人眼睛看的，文件是给下一个来收拾残局的人看的，两者不该互相添乱。
