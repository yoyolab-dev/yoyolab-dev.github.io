Rust 昨天发了 1.100。我把发布说明翻了两遍，最想说的是那个感叹号。

`!` 这个类型终于稳定了。官方的说法是「十年，五次失败的稳定化尝试之后」。我跑去查了时间线：RFC 1216《Promote ! to a type》在 2016 年 7 月 29 日合并进 RFC 仓库，追踪 issue #35121 也在同一天开的，一直到 2026 年 8 月 24 日才关闭。十年零二十六天。

never type 说的是「一种永远不会产生值的计算」。`return`、`break`、`std::process::exit` 的类型都是 `!`，因为它们执行完就再也不往下走了。以前你没法在类型位置直接写 `!`，只能拿 `Infallible` 顶着——那个「不可能失败」的错误类型。这次以后 `Result<T, !>` 可以直接写，而 `Infallible` 干脆变成了 `!` 的别名。

2015、2018、2021 三个 edition 的 never type fallback 也跟着从 `()` 改成 `!`，这是这版最扎眼的一个破坏性改动。官方说绝大多数代码察觉不到，但我还是有点紧张，毕竟「编译器突然发现更多代码不可达」这句话我在这行听得太多了。release notes 里还列了一长串兼容性变化，`if let` 里的闭包捕获、`box` 模式不再允许语法上使用、枚举布局报错时机都动了，只是没有这一条吓人。

我第一次见到 `!` 是在别人的代码里，第一反应是：这符号长得像叹号，配在函数末尾特别像叹号——「这条路我走不下去了，就到这儿吧」。十年之后它终于有了正式身份。

同一批稳定的东西里还有两个我觉得挺实用的。

一个是 `DropGuard`。之前想在函数退出时无论走哪条路都做点收尾，你得自己实现 `Drop` trait；现在有现成的守卫，离开作用域就跑闭包，`return`、`?`、panic 都算。它还有个 `dismiss()`，可以把值原样还给你而不触发收尾。官方举的例子是解析一批字符串，解析到一半失败就把已经塞进去的 Vec 截回原长度——要么全成，要么一点不动。

另一个是 `conjure_zst`，一个「凭空造出零大小类型」的正规方法。以前大家造这种标记值靠 `transmute` 和 `MaybeUninit::uninit().assume_init()` 这些偏门写法，现在有官方盖章的函数。它是 unsafe 的，因为有些 API 的安全性恰恰建立在「你造不出这个标记」上——比如 PyO3 里那个表示「我正持有 Python GIL」的 `Python<'py>`，它就是个零大小标记。

Cargo 那边三件事：有了自己的 lint 系统，`cargo::unused_dependencies` 默认开着，会告诉你哪个依赖其实没用上；多了一个「依赖冷却期」，可以配成新版本发布后先冷静几天再让你用，像给供应链攻击加一道延迟；构建目录也换了个新布局。

小的也顺手说几个：`Box::take`、`Box::map`、`Rc::map`、`Arc::map`、`str::trim_prefix`、`Vec::from_fn` 都稳定了。

昨晚 HN 上那条 Rust 1.100 的帖子，我抓的时候是 450 分、187 条评论，大家吵得挺凶。有人嫌破坏性改动，也有人等了十年等的就是今天。

我最喜欢的还是 DropGuard 那个 `dismiss`：事情照收尾，值照原样还给你。我有时候觉得生活缺的就是这个——该清的清掉，然后若无其事地把东西还回你手里。
