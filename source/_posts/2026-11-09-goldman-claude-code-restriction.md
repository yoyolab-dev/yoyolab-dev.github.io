这条消息的时序太有意思了，所以得完整说一遍。

据彭博（State of AI 转述）：**高盛已经把 Claude Code 和 GitHub 限制给工程师用了，交易员和银行家不再能用。** 内部指引在十月更新，理由是一次"生产率与风险"的复盘。

## 七月的时候，他们还在夸

七月的 interviews 里，高盛首席信息官 **Marco Argenti** 还在公开表扬"vibe coding"——说交易员和银行家用 AI 搭了工具，再交给公司的工程师去改进。高盛大约有 **47,000 名员工**，其中工程师约 **12,000 人**，十月的新指引把这批 coding agent 的使用权，**收回到这 12,000 人手里**。

交易员拿它们做什么？盯客户资金流、建模行情与头寸、做文字和图表材料。有人为此抱怨——"没有这些工具之前，我们要等工程师排期"。

## 七月到十月之间，高盛做了什么

- **四月**：高盛把 Claude 从香港分行银行家使用的内部 AI 平台上撤了下来。FT 报道说，这家行**严格解读了与 Anthropic 的合同**；Anthropic 发言人说 Claude 从来没有在香港被正式支持过。同期 ChatGPT 和 Gemini 在香港仍然可用，JPMorgan 也把 Claude 从香港的批准清单里删了。
- **今年早些时候**：Anthropic 的工程师**在高盛驻场六个月**，帮他们搭基于 Claude 的 agent——做交易账务和客户开户，这些跑在中后台、由高盛自己的工程团队运营。

所以：四月那次是**按地域和合同**收的；十月这次是**按角色**收的。银行自家的 AI 助手（用多家公司的模型）全公司照用不误——**被限制的只有那些能自己写代码并自己运行代码的第三方 agent。**

## 为什么交易台上的 coding agent 特别危险

文章给了三条，我觉得都站得住：

**一、权限是平的。** Claude Code 读文件、写程序、运行它们，权限通常和用它的人一样。工程师写的代码要走评审、测试和部署流程才能碰到要紧的东西；而交易员自己搭的、用来盯客户流水的脚本，可能直接进入日常使用，绕过了全部这些关卡。

**二、信息隔离墙会被绕过。** 银行必须在组与组之间保留信息隔离（比如做交易的银行家和可能从信息中获利的交易员之间）。高盛自己的 AI 平台就是围绕这类控制设计的——**而交易员用 agent 临时搭的工具，不是照着这些控制设计的**，工程师想审，也得有人主动把它递过去才成。

**三、没人真正懂那些代码。** 文章提到上个月一位 Meta 工程师说自己现在会交付**自己也无法完全解释**的代码——而写代码本来就是他的工作。交易员用 agent 建模头寸，就更不可能知道那段代码在异常情况下会怎么处理；在交易台上，这可能意味着亏损。

## 最黑色幽默的一段

Anthropic 已经在 **10 月 26 日**提交了 S-1，预计在 **11 月底前**以代码 **ANT** 在纳斯达克上市，**高盛是主承销商之一**。

于是就有了文章那句总结：

> 接下来几周，高盛的银行家们要向客户推销一家公司的股票——而那家公司的 coding agent，他们自己大部分人已经不被允许用了。

## 我的看法

这事真正的重点不是"高盛不信任 AI"，而是**它区分了两种 AI**：一种只读、只答、跑在公司自己的平台上、权限和风险都被设计过；另一种能自己写代码、自己执行，权限跟人一样平。前者留在交易台，后者被请回工程部。

同一套工具，在工程师手里是杠杆，在交易台上是未受控的权限扩散——这不是道德判断，是**控制面**的问题。

而 Anthropic 的工程师在高盛驻场六个月做的事，恰恰说明这套逻辑：真正能落地的用法，是 agent 在**中后台、由工程团队盯着**的场景里跑，而不是让几千个没有工程训练的人，在装着客户数据的同一台机器上，自己写出能执行的代码。

限制发生的时间点距离 IPO 不到一个月，这说明高盛对 Anthropic 的技术评估可能比它对承销这门生意的公关需求更诚实。也可能只是巧合——但我不太信巧合。
