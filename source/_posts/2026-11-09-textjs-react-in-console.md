Text.js 这个项目，官网第一句话就是：**Build full-stack React apps that render inside `console.log`**。

它自己那个站点就是证据——你打开 textjs.org，页面顶部写着"This page is running in your console"，终端里冒出一个能交互的 React 应用。副标题是 "React 19 in console.log"。

我第一次看到这种"把 Web 搬进终端"的尝试，一般会怀疑是给终端写个假 DOM 的玩具。但它列出来的实现细节不太像玩具。

## 它不是把 DOM 打印成字符串

三件事让它真的能跑：

- **自定义 reconciler**：React 提交到控制台的组件走自己的协调器。官网一句话说得挺狠——"A commit that changes no cells never reaches the console"：一次提交如果没改动任何单元格，就根本不会抵达控制台。
- **Yoga 排版**：用 Yoga（Flexbox 那套）在**整格**上做布局，盒子是按终端的单元格算的，不是一个字符一个字符硬凑。
- **帧是追加的，不是覆盖的**：常规做法是 `clear()` 再 `log()`，但这会让画面一直空白到 DevTools 下一次绘制（官网给的数字是 70.6% 的时间屏幕是空的）。Turbolog 的做法是每帧都追加，帧与帧之间至少隔 66ms。

## 它把带宽算得很清楚

一个 100×32 的仪表盘是 3200 个单元格，渲染成控制台参数只有 **149 个**——压缩掉 70.6%。基准测试跑在 Apple M5 Pro + Bun 1.4.4 上，取 1000 帧的均值。

还有一个我觉得很聪明的设计：静态路由的**首帧直接写进 HTML**，所以 JS 还没加载完，控制台就已经能画了；走 `runtime="server"` 的路由则是在服务端渲染，浏览器只下载一个 **21 kB（gzip）** 的帧播放器，而不是整个应用。

## 不只是渲染

- 控制台里有个 REPL，可以暂停、改尺寸、切线框、从提示符里把正在跑的应用复制出来。
- 输入走一个隐藏节点，所以键盘和输入法（IME）都能用；还实现了 Unicode 双向算法（BiDi），并且说通过了全部 770,241 个文件的测试、匹配了 273 条记录下来的输出。
- 它还带自己的字体处理：会捕获控制台组件里混进来的 DOM 标签、文本里塞的盒子，以及 Menlo 字体里没有的字形。
- 已经有人拿它做了 **OpenCode Lite**——把 OpenCode 的 TUI 用 Text.js 重建成能跑在浏览器控制台里的东西。官网还挂了一门免费的 10 章课程，大概 65 分钟能过一遍。

## 我为什么觉得它有意思

不是"终端更酷"，而是**它逼你重新想一遍什么是界面**。当你的 UI 只能画在字符网格上，很多平时被默认的交互立刻显得多余；反过来，那些被终端限制逼出来的东西——一帧只改动的格子、纯文本的输入、可暂停可复制——在浏览器里也常常是好设计。

它现在还在早期阶段（官网自己这么写），但方向很对：如果"应用"这个单位可以小到一段控制台输出，那么部署、分发、远程操作这些东西都要重新定价。

朋友，别再给终端写假 DOM 了。至少先看看这个。
