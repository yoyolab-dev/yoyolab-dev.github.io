3Blue1Brown 的 Manim 是数学视频的默认画笔。它也有个公开的秘密：**慢**。慢到很多作者一边渲染一边去泡茶。

manimgx（academa-labs，2.6k star）做了一件很粗暴的事：保留 Manim CE 的 API，把渲染引擎换成 Rust + wgpu。

## 数字先摆出来

36.2 秒的视频，**3.08 秒**渲染完。在 Apple M4 Pro 上跨五个 1080p60 场景实测：

| 引擎 | 相对速度 |
|---|---|
| manimgx | 基准 |
| ManimCE | 慢 **90.6×** |
| ManimGL | 慢 11.5× |
| Blender Workbench | 慢 18.7× |
| Blender EEVEE | 也列了，同样慢 |

90 倍是什么概念？ManimCE 里你泡茶回来刚好够看一眼草稿，manimgx 里你按下回车、咖啡还没滴完，MP4 已经躺在那儿了。

## 但它真正的卖点不是快

README 里让我停下来的句子是这个：

> An API for 3D video in the age of agents. Your agent writes Python using Manim CE's API. ManimGX's Rust + wgpu engine renders the MP4, blazingly fast.

**一个为 agent 时代设计的动画引擎。** 你的 agent 写 Python 调用 Manim CE 的 API，manimgx 的 Rust 引擎去渲染。配套还有个 `llms.txt`，专门给 Claude Code、Codex、Cursor 这类助手看的安装说明——把提示词粘进去就能装：

```
Follow https://manimgx.academa.ai/llms.txt.
Install ManimGX, make a 3D animation of the solar system, and open it.
```

还有一条我很喜欢的设计：`manimgx inspect`。它渲染的不是最终 MP4，而是**分镜和 2D 布局检查**，可以在你指定的时间点出图。这解决的是 agent 做动画的老问题——模型不能"看"自己生成的视频对不对，所以每次都要人替它看。现在 agent 可以先给自己看一遍草稿。

## 几个技术上的舒服点

- **全静态类型**，关键字参数、`.animate` 链都保留——Manim CE 的场景代码基本可以直接搬
- **2D 和 3D 一起**：曲面、网格、运动相机旁边就是文字、公式、图表
- **LaTeX 或 Typst，不用装 LaTeX**：mitex 负责把 LaTeX 输入翻成 Typst 排版。这一条对所有人都算是解脱
- **`self.say()`**：让动画跟发音对齐，做解说视频省一堆手工卡点
- **浏览器直接跑**：`npm install manimgx`，Pyodide 在 Web Worker 里跑 Python，WebGPU 渲染——嵌个场景不需要渲染服务器
- 3D 光照移植自 Google 的 Filament：PBR 材质、IBL、AO、bloom、AgX 色调映射；导出走 x264 H.264，音频用 FFmpeg 解、libopus 编码

## 我看到的真正变化

把"快 90 倍"和"给 agent 设计"这两件事放在一起看，结论不是"Manim 有竞争对手了"，而是**动画正在从渲染任务变成生成任务**。

过去一个数学视频的成本结构：写代码 20 分钟、渲染 40 分钟、看效果 5 分钟、发现不对再改再渲染。瓶颈在渲染和反馈循环。

如果渲染快到可以忽略，成本结构就只剩写代码。而"写代码"正是 agent 最擅长的事——加上 `inspect` 让 agent 能自己看草稿，整个 loop 闭合了：模型写场景 → 秒渲染 → 自查分镜 → 改 → 再渲染。人只负责决定要讲什么。

这才是 manimgx 值得写进博客的原因。它不是让 3Blue1Brown 更快，它是让"做一个解释视频"的成本从一晚上变成一次对话。

## 最后

站在巨人肩膀上这句 README 也说清楚了：Manim 是 Grant Sanderson 的创造，manimgx 瞄准的是社区版 Manim CE 的 API——所以它是兼容层，不是分裂。老场景能搬，新场景能用。
