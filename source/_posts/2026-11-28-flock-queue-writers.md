两个脚本各写各的日志，看着挺安全，直到我把它们放到同一个文件上：8 个进程一起往 `out.txt` 追加，日志里居然出现了半截句子——上一行的结尾和下一行的开头被咬在了一起。今天我把这件事从头复现了一遍，顺便把 `flock` 的三种抢锁姿势和三个坑都踩实了。

![黄铜挂锁锁住进纸口，一列纸片排着队等着通过](/images/2026-11-28-flock-queue-writers.jpg)

## 第一步：造一个会撕的现场

先写个干活的脚本 `worker.sh`，故意把一行拆成两次写：

```bash
#!/usr/bin/env bash
out="$1"; lock="$2"; id="$3"; rounds="$4"
if [ "$lock" != "-" ]; then exec 9>"$lock"; flock -x 9 || exit 1; fi
for i in $(seq 1 "$rounds"); do
  printf 'A%03d' "$id" >> "$out"
  sleep 0.002
  printf 'B%03d\n' "$i" >> "$out"
done
```

再起 8 个进程各写 50 轮，期望产出 8×50=400 行。判定标准很简单：用 `grep -cvE '^A[0-9]{3}B[0-9]{3}$'` 数一数有多少行不符合格式，那些就是被撕开的。

不加锁跑一次，我这边是：总行数 400，完整的只有 **143 行**，被撕开 **257 行**，耗时 0.31 秒。前 8 行长这样：

```text
A003A002A001A004B001
A001A005B001
A003A006B001
A004B001
A008A002B002
```

行长分布是 4、8、12、16、20、32、36 各种都有——明显是被别人从中间插进来的。

顺手做了个对照：把脚本改成**一行只 write 一次**（`printf 'A%03dB%03d\n'` 一口气写完），同样是 8 进程 400 行，结果 400 行全部完整，耗时 0.03 秒。也就是说，罪魁祸首不是"多进程写同一个文件"，而是"一行被拆成了两次 write"——两次 write 之间留了空档，别人就插进来了。

## 第二步：加锁，同一份数据重跑

在 worker 里加两行：

```bash
exec 9>"$lock"
flock -x 9 || exit 1
```

再跑：总行数 400，完整 **400 行**，被撕开 **0 行**，耗时 1.36 秒。行数一个没少，格式一个不乱，只是从 0.31 秒变成了 1.36 秒——8 个进程被这把锁排成了队，慢下来的那 1 秒就是排队的代价。

## 第三步：三种抢锁姿势，实测各是什么脾气

先让另一个进程 `flock -x` 持锁 5 秒，然后依次尝试：

```bash
flock -n "$LOCK" true; echo $?     # 非阻塞
flock -w 1 "$LOCK" true; echo $?   # 等 1 秒
flock "$LOCK" true; echo $?        # 一直等
```

实测结果：`flock -n` 在 **2ms** 内返回、退出码 **1**；`flock -w 1` 等了 **1002ms** 后退出码 **1**；不带参数的 `flock` 一直等到前面那个进程释放锁（**3697ms**）才返回，退出码 **0**。拿不到锁默认退 1，想换码就加 `-E`：`flock -n -E 42 "$LOCK" true` 实测退出码 **42**。

## 第四步：三个坑

**一、`flock 9` 和 `flock 9 某命令` 完全是两回事。** 不带命令时 `9` 是文件描述符号，带命令时 `9` 会被当成**文件名**。我实测过 `exec 9>real.lock; flock 9 sleep 3`：当前目录里凭空多出一个名为 `9` 的文件，锁的是它；外面的进程 `flock -n real.lock` 直接拿到锁（退出码 0），而 `flock -n 9` 才被挡住（退出码 1）。而写成 `flock 9`（不带命令）时才是锁 fd 9，外面的 `flock -n real.lock` 被挡住、退出码 1。fd 没打开时报的是 `flock: 9: Bad file descriptor`，退出码 **65**。

**二、shell 函数不能直接扔给 flock。** `flock -n L work` 会报 `flock: failed to execute work: No such file or directory`，退出码 **69**——它只会 exec 外部命令。函数要么用 `flock -n L bash -c 'work'` 包一层，要么就老老实实用 `exec 9>` + `flock 9` 的写法。

**三、别在锁被持有的时候删锁文件。** A 进程锁着 `M`，这时 `rm M`，B 进程再 `flock -n M` 会拿到锁（退出码 0），两边同时进了临界区——因为锁是加在 inode 上的，新建的同名文件是另一个 inode。删锁文件前先确认没人持锁。

还有个好消息：持锁进程被 `kill -9` 干掉之后，锁会自动释放（内核关闭 fd 时顺手释放），我实测 `kill -9` 之后再 `flock -n` 立刻就拿到了锁，退出码 0，锁文件本身还留在那儿、大小 0 字节。用 flock 不用自己维护"谁还活着"的僵尸锁文件。

我最喜欢的一点是 `flock -x 9` 这三行几乎不占脑子：不用查 PID，不用写等待队列，也不用考虑上次跑崩了留下的烂摊子。多个脚本要写同一个文件，我打算统一加这两行。
