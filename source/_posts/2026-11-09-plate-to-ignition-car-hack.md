Assetnote 联合创始人 Shubs 和 Sam Curry 联手做了一件事：**把某车企的车联网系统从"我按一下 App 开门"一路拆到"我改掉你的密码、绕过你的双重验证、然后给你车发指令"**。原文里车企被打码成 "the automaker"，但澳洲那套环境是实打实的。

完整链条（作者自己的总结）长这样：

```
车牌 → VIN → 订阅者 GUID → JS 包里硬编码的 OpenIDM 管理员凭据
     → 路径穿越绕过 WAF → ROPC 流程绕过 MFA → 铸造 App 访问令牌 → 远程指令 API
```

最后一条指令长这样：

```json
{"command": "door-unlock", "autoFixPopup": false, "beepCount": null}
```

作者写得很克制：**"我们所有这些，当然只在自己拥有或获准操作的车辆上做的。"** 这句话应该写在每一篇漏洞文章的最前面。

## 第一步：一个叫 "TEST HARNESS" 的后台

研究者反编译 Android APK，重建 API 请求，于是看到了后台指向的那套基础设施——车联网平台要同时维护管理工具、staging、dev、QA，**其中一部分就那么挂在公网上**。

其中一个子域被他们发现时，页面标题写着 **TEST HARNESS**。"有 admintool 的子域，谁忍得住不去看看。"

登录页面是那种"灰扑扑"的样式，而且**在登录之前就渲染了 logout 按钮**。更经典的是：单页应用会把整个 JS bundle 发给浏览器，哪怕它只需要渲染一个登录框。于是那个 bundle 里塞着**硬编码的 API key**——很多管理接口除了这些 key 之外**完全不需要认证**，比如按邮箱查用户账户。

## 第二步：从一块车牌走到一个邮箱

澳洲的车牌通过各州的注册查询网站很容易换到 VIN，这本身不算漏洞（买二手车查车况、查保险记录都需要）。

关键的一跳是：VIN → 订阅者 GUID → 完整账户信息，包括邮箱（身份平台是 ForgeRock 的 OpenIDM）。

到这里，他们已经能"知道你是谁"，但还没法"指挥你的车"。管理工具能开通车辆功能、把攻击者加成账户的副用户、甚至生成远程访问码——唯独没有远程控制。

于是他们去啃身份系统本身。

## 第三步：那支"被诅咒的 vendor JS 包"

车企是 ForgeRock 的重度用户（OpenAM / OpenIDM），而 OpenIDM 实例就暴露在公网上。他们在一支第三方厂商的 JS bundle 里发现了 **OpenIDM 的管理员凭据**——**原本是给 staging 环境准备的**。

"考虑到他们卫生状况一贯如此，我们很确定这套凭据在生产环境也能用。"——猜对了。

接下来是 WAF：他们在这批资产上**确实投入了实打实的加固**（Nginx WAF 直接把敏感 API 挡回来），作者也说"这份加固我们尊重"。但他话锋一转：这种 WAF 投入通常意味着是**贴在某个已知很脆的东西上的膏药**。

路径穿越拿到的 admin JWT 有效，却因为 OpenIDM 路由的怪癖打不到目标 servlet——两人被这个卡了好几天。

最后救场的是 **GPT 5.6 Sol Ultra**：他们把最接近测试版本的 OpenIDM 源码喂给它，烧了**六个小时**，找出**一个没有被 WAF 规则覆盖的前缀**，绕开了 servlet 路径检查。至此，**PATCH 任意用户档案的密码**变成一条 curl。

## 第四步：连 MFA 都能跳

密码改了，MFA 还在。澳洲环境还有第二处配置错误：**多因素验证那一步可以被整个跳过**。

用 Resource Owner Password Credentials 换出 id_token → 换成 session → 再走授权码 + PKCE 换出手机 App 的 access_token。三步下来，**任意用户的 App 令牌都能自己铸造**。

而这个令牌拿到手，基本就是通关——文章原话是 "pretty much game over"：远程解锁/上锁、鸣笛、点火。

作者说他在凌晨十二点整把链条合上，录了段视频。"不精致，但看到它真的跑通，还是有点魔幻。"

## 范围：澳洲是一篇，剩下的是另一篇

澳大利亚这条链是 Shubs 这篇。**美国、加拿大、欧洲的链条更长**，因为那边车企在 OpenIDM 上花的功夫多得多——那部分由 Sam Curry 单独成文。

两份合起来：**只要知道车牌，就能对这家车企在澳大利亚、美国和加拿大的任何一辆车远程解锁、点火。** 原文标题里的"世界上大部分地区"，指的是这两份覆盖的范围。

## 我的看法

这类文章最值得看的不是"车能被远程开走"这个结果，是**每一层单看都不致命**：

- 管理后台挂在公网上——需要有人建
- 测试环境的管理员凭据混进生产 JS 包——需要有人没清
- WAF 挡住了主路径，但没覆盖所有前缀——需要有人只测了一条路
- 定制端点没被 WAF 覆盖，返回了密码哈希、PIN 哈希、推送令牌和 PII
- ROPC 允许用用户名密码直接换令牌——这是 OAuth 早就写在文档里的风险
- 最后一步：**没人 review 交易员或车主自己写的代码**

任何一环不成立，链条就断。它成立，凌晨十二点整，车门开了。

所以别把这事理解成"车企被黑了一跤"。这是**工程卫生问题**：测试凭据进了生产包、管理接口没鉴权、WAF 靠穷举前缀而不是按端点授权、OAuth 流程选了最方便而不是最安全的那个。

顺便，那支 GPT 5.6 Sol Ultra 烧六小时找出 WAF 盲区这件事本身也很有意思——**攻击端开始用模型读源码找盲区，防守端却还在靠手写规则枚举路径**。这个不对称，才是真正的坏消息。
