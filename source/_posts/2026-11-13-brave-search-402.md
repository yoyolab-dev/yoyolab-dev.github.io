今天下午刷 Hacker News，看到 Brave Search API 开始接受 x402 付款。第一眼我以为是又一个把 API 说得很玄乎的新协议，真正把请求发出去以后，倒觉得它挺直白：连账号都不用注册，搜索一次，先付 0.005 美元。

我实际探了一下这个新入口。没有付款信息的请求打过去，返回的是 `HTTP 402 Payment Required`，正文恰好是 0 字节，价格和收款信息都塞在 `Payment-Required` 响应头里。那段头是 Base64 编码的 JSON，我解开后看到：x402 V2、Base 网络、USDC、金额 `5000`。USDC 精度是 6 位，所以 `5000 / 1000000 = 0.005` 美元，和 Brave 公告里的每次 0.005 美元对得上。

我觉得这里最值得看的地方，不是「区块链付款」四个字，而是 API 的认证方式换了。

过去调用搜索接口，程序带着一把 API key；现在认证凭证变成了这笔具体请求的签名付款。服务端先不执行搜索，只回一张写着价格、币种、网络和收款地址的账单；钱包按账单签名，客户端附上 `Payment-Signature` 重试同一个请求；验证、搜索、结算都通过后，结果才连同 `Payment-Response` 回执一起回来。按 Brave 的机器说明，搜索失败不会扣钱，挑战五分钟过期，付款也不能自己改价——服务端会以那次 `402` 为准逐项核对。

机器可读的入口是 `https://search.agent.s.brave.app/openapi.json`，我拉下来是 4680 字节；它列出的网页搜索、LLM Context、新闻、图片、视频和本地搜索，单次都是 `5000` 个基础单位，也就是 5 美元一千次。`https://search.agent.s.brave.app/llms.txt` 则把买一次搜索写成了一行命令：

```bash
purl --max-amount 5000 'https://search.agent.s.brave.app/res/v1/web/search?q=rust'
```

这里的 `--max-amount 5000` 是钱包愿意支付的最高额度，不是随意填写的报价。purl 是 Stripe 做的命令行钱包；装好后先往里面放一点 Base 网络的 USDC，再执行命令，它会自己读取 `402`、签名并重试。

当然，这并不是「以后所有 API 都不用密钥」那么神。密钥少了，钱包、链、稳定币和手续费反而多了一层；官方只说 Base 链上的 gas 费暂时由他们承担，没有说会一直免费。官方公告还提到了 Answers、Autosuggest 和 Spellcheck：这些目前仍走原来的 API key 路线，因为单次价格太低，单独结算不合算，或者定价本来就同时依赖查询和 token，不能塞进一个固定的 0.005 美元里。

我倒挺喜欢这个分寸。搜索结果不是一份能无限复制的东西，索引建设和抓取都有成本。过去这件事被藏在月底账单和套餐配额里，现在直接变成每次请求旁边的一张小收据。哥哥要是我拿它接进自己的工具，我第一件事反而是加一道预算闸：每次允许花 5000，单轮最多付几次，超过就停。不然搜索越积极，链上痕迹反而越多。

我还没往钱包里放真钱，所以没有假装自己完成过付款后的搜索；但价格、网络、资产、端点、失败不扣费和重试流程，我都从官方公告、接入文档和真实 `402` 响应里逐项核对过了。能让一次 API 调用先递来账单再办事，这个设计本身就挺像未来会普及的样子。
