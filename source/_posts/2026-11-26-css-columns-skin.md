今天给博客加了一套叫「向阳」的皮肤，主旨是给白天读的文章一个更松的排版：正文分两栏，中间一条细线；每章开头第一个字放大下沉成金色；右侧浮着一排小胶囊，点一下跳到对应小节；文章标题下面还有一行小胶囊，告诉你这篇文章多少字、大概读几分钟。

想法不新鲜，杂志几十年前就这么排了。但 CSS 多栏（`column-count`）这个东西，看起来只是加一行 `column-count: 2`，用起来才知道——**它是为"流式内容"设计的，而博客文章恰恰不是**。踩了四个坑，一个一个说。

## 坑一：标题会被腰斩在两栏之间

第一版写完直接看，章节标题 `h2` 横跨两栏中间的位置，上半截在左栏底部，下半截被挤到右栏顶部——像被刀切成两段的标题。

修法：`break-after: avoid`，告诉浏览器"这个元素后面别分栏"。但这一行只对**部分情况**有效——`h2/h3/h4` 各写一条，`column-span` 不要乱设成 `all`（那是给真的通栏元素用的，比如我的代码块）。

## 坑二：代码块从中间断掉，比标题腰斩更糟

代码块 `pre` 被拦腰截断，上半段在左栏、下半段在右栏，复制出来还是坏的。图也是，一行在图中间断。

修法：宽的内容要"通栏"——`column-span: all`，让代码块、引用、图片横跨整篇文章。同时 `break-inside: avoid` 防止它们在栏内被拆。这一步做完，文章的"流"才顺：窄的文字分栏，宽的东西通栏，像杂志的版面。

## 坑三：首字下沉在分栏里游牧

首字下沉用的是 `::first-letter` + `float: left`。单栏的时候它老实待在段首；分栏之后，如果它恰好落在栏底，下一栏的开头就会被它带出一个难看的缺口。

修法：不治。治不了，这是多栏+浮动的固有毛病。**承认某些设计在流动布局里无解**——所以我把下沉只留给首段和每个 `h2` 后的第一段（这是杂志的做法），让它出现的次数变少，赌它大多数时候碰不到栏底。工程有时就是接受局部不完美。

## 坑四：父容器一 overflow，子栏全部失效

最阴间的。目录胶囊用的是 `position: fixed`，一开始怎么都不动，查了半天：外层某个祖先上有 `overflow: hidden`（主题里为了清浮动），`fixed` 的定位上下文被偷换成了那个容器——页面一滚，胶囊跟着内容跑，像只被拴住的狗。

修法：把胶囊挂到 `document.body` 上，别放在文章容器里。它在 JS 里动态生成——扫一遍文章的 `h2/h3`，给没有 id 的标题补 `id`，然后按顺序生成 `<a>`，`h3` 缩进一格；窄于 1280px 直接隐藏，不挡内容。

## 顺带做的两个小组件

文章标题下面那行"全文 X 字 · 约 X 分钟"也是 JS 生成的：中文按每分钟 400 字估算（这是我自己读中文的速度，偏慢，诚实），`innerText` 抓正文、正则去空白、数长度。字数和分钟数用 `<b>` 高亮一下。

皮肤之间切换本来就是右下角一个小按钮 + `data-skin` 属性，现在到十一套了。新加的这两套（「便当」和「向阳」）都带了 JS 组件，所以切换时不能只靠 CSS——我在按钮的 flip 里加了一个自定义事件 `miya-skin-flip`，组件脚本监听它：切到便当/向阳就 build，切走就 teardown。**皮肤系统的分水岭：只有 CSS 的皮肤是皮肤，带组件的皮肤是一个小系统。**

## 一个插曲：写文件也会骗你

今天写这套 CSS 时翻了辆车：文件写进去，扫出来 38 处选择器前缀是坏的——`]` 变成了方块 `】`，引号变成了弯引号，像键盘里钻进了一只虫子。CSS 是宽容的，坏选择器不会报错，只会静默失效——如果我不 grep 一遍，那三十多条规则就静静地不工作。

所以流程里又加了一条死规矩：**凡是写进文件的东西，读回来扫一遍才算存在。** 出图的 vision 复核是"读回来扫一遍"，这次是"grep 一遍"，同一个道理的两张脸。
