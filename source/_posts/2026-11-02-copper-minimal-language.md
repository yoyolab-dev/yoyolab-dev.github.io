晚上刷 HN，首页挂着一个新项目：Copper。作者 Marc Kerbiquet 说，这是他拿来替掉 C 的语言。184 分，103 条评论，评论区自然分成两派：一派说语法干净得像 Ruby，另一派逐行挑毛病。我两边都读了一遍，觉得这场架比语言本身还有意思。

他的出发点写在第一段：极简是最重要的特性，"这门语言要简单到像我这样脑子不太好使的人也能完整理解它"。听着像谦辞，其实是设计纲领——它不是为团队协作设计的，是为一个人能全记住而设计的。

列出来的差异挺杂：任何类型都能继承、泛型、多返回值、定义顺序无所谓、导入不需要头文件、defer、块迭代器、Ruby 风格语法、Option 类型。文档里最反常识的一条是，Copper 只操作对象的引用，整数也不例外，只不过整数被看作无状态对象的引用。所以 `var a = 5` 会直接报错，没有"默认整数类型"这回事，你得写 `var a = Int32: 5`。而声明变量时用的又是后置的 `var a: Int32`。同一份文档里两种相反的写法，HN 立刻有人抓住，作者只回了一句"文档可能过时了"。

再往下有两个设计我挺喜欢。

一个是 Option 类型。`T?` 表示"可能是 T，也可能是 nil"，安全用法是先跟 nil 比一次，编译器就把变量自动提升回 T：

```
var v = getValue      // v 是 T?
if v == nil
    return
end
// 到这里 v 已经是 T
```

这招比 Rust 的 unwrap 温和，也比 C++20 的 optional 好读，代价是得信编译器没看漏。

另一个是块不是真闭包，是卫生宏。作者自己交代：传进来的块会被直接内联进调用者函数，效率很高，但宏写太大二进制就会撑爆。自己吐槽自己的设计，这种诚实现在不多见。

最让我坐直的是他的博客里那篇《My Take on Exceptions》。他曾经在自己语言里实现异常，做了 unwind 语句，还发现 Zig 有个 errdefer 对应的东西，然后整套异常机制又被他全部删掉了，那一节的标题叫 "Anddd It's Gone"。

理由不是"异常不好用"这种大话，是几条具体的：错误码会被忘，所以 C 有 warn_unused_result，C++17 有 [[nodiscard]]，他给类型挂一个 mustcheck 指令，让错误类型没法被忽略；程序员的错误（除零、越界）和真正的业务错误该分开，前者发现就该停；最激进的一条是，最好的错误处理是压根没有错误——文件整个读进内存，就不会有 IO 错误；输入提前校验干净，核心逻辑就不必处理错误；资源嵌进二进制，连文件都不读。

他还贴了一段 Java 骂"异常导向编程"：用 catch 越界异常来代替边界检查，算法最后其实是错的——第一个数组比较短的时候，那个函数会返回 true。

变更日志更能说明这门语言的脾气。十一个大版本，篇幅大半在删。v8.0 一次砍掉 `++`/`--`、默认参数、多行字符串、begin 块，把 static 换成更短的 func/attr/def；v10.0 改了引用语法，把泛型参数里的 `: *` 去掉，只留一个 cast 方法。加东西的版本反而是少数。

编译器自己也用 Copper 写，源码浏览页上摆着 main.co、generator-c.co、generator-llvm.co、generator-x64.co、object-file-elf64.co，能看出有 C、LLVM、x64 几条后端。

HN 上最欢乐的一段是文件扩展名。有人吐槽这语言叫 Copper，扩展名既没敢用 .cu（CUDA 占了），也不该是 .co。作者被戳到痛处，回了个链接，什么也没多说。

我现在很少见到有人敢把"我脑子不太好使，所以我把语言做小"当成设计目标。Rust 和 Zig 都在往"给你更多能力、自己负责"的方向走，Copper 反着来，删到只剩必须。而且他删异常那篇，比大多数语言设计文章诚实——他不是在论证自己的语言好，是把自己绕过的弯一条条摊开：试过，做过，发现不值，于是拆掉。

改天要是有个小工具想写，我可能会拿它练手。反正它有 defer，有 Option，语法看着像 Ruby。到底多好用，两周之后我再说。
